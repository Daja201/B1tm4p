STACK
- Docker Compose, 3 services: "backend" (Node.js 20 + Express, better-sqlite3), "frontend" (nginx serving static HTML/CSS/vanilla JS), optionally "mailer" folded into backend using nodemailer.
- Shared named volume "b1tm4p_data" mounted at /data in backend, containing:
  /data/db/users.db
  /data/db/tags.db
  /data/db/content.db
  /data/db/reports.db
  /data/uploads/avatars/
  /data/uploads/mastertag_headers/
  /data/uploads/media/images/
  /data/uploads/media/sound/
  /data/uploads/media/video/
- All 4 databases are SEPARATE SQLite files opened as separate connections in the same backend process. Do not merge them into one file. Use foreign-key-style integer IDs across files but DO NOT use SQLite ATTACH or cross-file JOINs — resolve joins in application code (fetch IDs from one db, then query the other). This is intentional for modularity.
- better-sqlite3 (synchronous) is mandatory — no async sqlite3 driver, to avoid race-condition bugs in a small team split across 3 AI sessions.

AUTH MODEL
- Password hashing: bcrypt (bcryptjs), cost factor 10.
- Sessions: server-side session table in users.db (NOT JWT), cookie name "b1tm4p_sid", httpOnly, sameSite=lax, 30-day expiry, random 32-byte hex token stored hashed (sha256) in DB.
- Every authenticated request reads the cookie, hashes it, looks up sessions table, attaches req.user = {id, email, username, role, avatar_type, avatar_value, avatar_shape}.
- Unauthenticated requests to protected routes return 401 {"error":"unauthorized"}.
- Role enum stored as TEXT CHECK constraint: 'user','support','manager','admin'. Default new registrations = 'user'.
- Admin account: on backend boot, check if a user with email=ADMIN_EMAIL exists in users.db; if not, create it with role='admin', password=bcrypt(ADMIN_INITIAL_PASSWORD), username='admin', avatar_type='initials', avatar_value='AD', avatar_shape='square'.

AVATAR MODEL (this must work correctly, it was previously broken)
users.avatar_type TEXT CHECK(avatar_type IN ('image','initials')) NOT NULL DEFAULT 'initials'
users.avatar_value TEXT NOT NULL  -- if type='image': relative path like '/uploads/avatars/<uuid>.webp'; if type='initials': 1-2 uppercase ASCII chars, regex ^[A-Z0-9]{1,2}$
users.avatar_shape TEXT CHECK(avatar_shape IN ('circle','square')) NOT NULL DEFAULT 'circle'
users.avatar_color TEXT NOT NULL DEFAULT '#FF7A00'  -- background hex color when type='initials'
RULE: avatar_shape='square' is only settable server-side if role IN ('admin','manager'); if a 'user' or 'support' role tries to PATCH avatar_shape to 'square', backend must reject with 403 {"error":"square avatars reserved for staff"}. This check happens on every PATCH /api/v1/account/avatar call, re-reading current role from DB, not from stale session data.
Image avatar upload: accept jpg/png/webp/gif, max 5MB, resize/convert server-side to 256x256 webp using the "sharp" npm package, store under /data/uploads/avatars/<userId>_<timestamp>.webp, old file deleted when replaced.

API CONVENTIONS
- All routes prefixed /api/v1/
- JSON bodies in, JSON out. File uploads via multipart/form-data (multer), max size from UPLOAD_MAX_MB.
- Success responses: whatever shape makes sense, documented per-route.
- Error responses ALWAYS: {"error": "<machine-safe-lowercase-string>"} with correct HTTP status (400/401/403/404/409/500).
- Timestamps: INTEGER unix epoch seconds, UTC, generated server-side with Date.now()/1000|0 — never trust client-sent timestamps.
- Pagination: all list endpoints accept ?limit=20&offset=0, default limit 20, max limit 100, return {"items":[...], "total": N}.
- CORS: backend allows requests from frontend origin only (configurable via .env FRONTEND_ORIGIN), credentials:true.

# B1tm4p API Contract

This is the authoritative contract for the backend-core service. All timestamps are integer Unix epoch seconds generated by the server. JSON errors always have the form `{"error":"machine_safe_lowercase"}`. List endpoints accept `limit` (default 20, max 100) and `offset` (default 0), and return `{ "items": [], "total": N }` unless otherwise stated.

## Databases

The backend opens these as separate SQLite connections. SQLite `ATTACH`, cross-file joins, and cross-file foreign keys are not used.

### `users.db`

```sql
CREATE TABLE IF NOT EXISTS users (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 email TEXT UNIQUE NOT NULL,
 username TEXT UNIQUE NOT NULL,
 password_hash TEXT NOT NULL,
 role TEXT NOT NULL CHECK(role IN ('user','support','manager','admin')) DEFAULT 'user',
 avatar_type TEXT NOT NULL CHECK(avatar_type IN ('image','initials')) DEFAULT 'initials',
 avatar_value TEXT NOT NULL DEFAULT 'US',
 avatar_shape TEXT NOT NULL CHECK(avatar_shape IN ('circle','square')) DEFAULT 'circle',
 avatar_color TEXT NOT NULL DEFAULT '#FF7A00',
 email_verified INTEGER NOT NULL DEFAULT 0,
 created_at INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS sessions (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 user_id INTEGER NOT NULL REFERENCES users(id),
 token_hash TEXT UNIQUE NOT NULL,
 created_at INTEGER NOT NULL,
 expires_at INTEGER NOT NULL,
 ip TEXT,
 user_agent TEXT
);
CREATE TABLE IF NOT EXISTS login_history (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 user_id INTEGER,
 ip TEXT NOT NULL,
 user_agent TEXT,
 device_label TEXT,
 success INTEGER NOT NULL,
 created_at INTEGER NOT NULL,
 raw_email_attempted TEXT
);
CREATE TABLE IF NOT EXISTS email_tokens (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 user_id INTEGER NOT NULL,
 token_hash TEXT UNIQUE NOT NULL,
 purpose TEXT NOT NULL CHECK(purpose IN ('verify','login_link','password_reset')),
 expires_at INTEGER NOT NULL,
 used INTEGER NOT NULL DEFAULT 0,
 created_at INTEGER NOT NULL
);
```
`login_history.user_id` is intentionally nullable to record unknown-email attempts; `raw_email_attempted` stores the attempted email when available.

### `tags.db`

```sql
CREATE TABLE IF NOT EXISTS master_tags (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 name TEXT UNIQUE NOT NULL,
 slug TEXT UNIQUE NOT NULL,
 header_image_path TEXT,
 description TEXT,
 created_by INTEGER NOT NULL,
 created_at INTEGER NOT NULL,
 updated_at INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS tags (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 master_tag_id INTEGER NOT NULL,
 name TEXT NOT NULL,
 slug TEXT NOT NULL,
 created_by INTEGER NOT NULL,
 created_at INTEGER NOT NULL,
 UNIQUE(master_tag_id, slug)
);
CREATE TABLE IF NOT EXISTS tag_requests (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 request_type TEXT NOT NULL CHECK(request_type IN ('master_tag','tag')),
 proposed_name TEXT NOT NULL,
 parent_master_tag_id INTEGER,
 requested_by INTEGER NOT NULL,
 status TEXT NOT NULL CHECK(status IN ('pending','approved','rejected')) DEFAULT 'pending',
 reviewed_by INTEGER,
 review_note TEXT,
 created_at INTEGER NOT NULL,
 reviewed_at INTEGER
);
```
Integer IDs such as `created_by`, `requested_by`, and `reviewed_by` refer to `users.db` IDs and are resolved in application code.

## Authentication

### POST `/api/v1/auth/register`
Auth: none.
Request: `{ "email":"a@example.com", "username":"alice", "password":"minimum8" }`.
Creates role `user`, `email_verified=0`, and a `verify` token; sends a verification email.
Response 201: `{ "id":1, "email":"a@example.com", "username":"alice" }`.
Errors: 400 `invalid_input`, 409 `already_exists`.

### GET `/api/v1/auth/verify?token=...`
Auth: none.
Consumes a valid, unexpired `verify` token and sets `email_verified=1`.
Response 200: `{ "ok":true }`. Invalid/expired token: 400 `invalid_token`.

### POST `/api/v1/auth/login`
Auth: none.
Request: `{ "email":"a@example.com", "password":"minimum8" }`.
Success creates a 30-day session and cookie.
Response 200: user object returned by `/api/v1/me`.
Errors: 403 `email_not_verified`; 401 `invalid_credentials`.
Every attempt creates `login_history`; unknown emails use nullable `user_id`.

### POST `/api/v1/auth/login-link`
Auth: none.
Request: `{ "email":"a@example.com" }`.
Response always 200: `{ "ok":true }`. Existing verified users receive a 30-minute magic-link email.

### GET `/api/v1/auth/login-link?token=...`
Auth: none.
Consumes a valid login-link token, creates the session cookie, and records a successful login-history entry.
Response 200: `{ "ok":true }`; invalid/expired: 400 `invalid_token`.

### POST `/api/v1/auth/logout`
Auth: required.
Response 200: `{ "ok":true }`; deletes current session and clears cookie.

### POST `/api/v1/auth/password-reset-request`
Auth: none.
Request: `{ "email":"a@example.com" }`.
Response always 200: `{ "ok":true }`. Existing users receive a one-hour reset email.

### POST `/api/v1/auth/password-reset`
Auth: none.
Request: `{ "token":"...", "new_password":"minimum8" }`.
Consumes reset token, updates password, invalidates existing sessions.
Response 200: `{ "ok":true }`. Errors: 400 `invalid_password` or `invalid_token`.

### GET `/api/v1/me`
Auth: required.
Response 200:
```json
{"id":1,"email":"a@example.com","username":"alice","role":"user","avatar_type":"initials","avatar_value":"AL","avatar_shape":"circle","avatar_color":"#FF7A00","email_verified":true,"created_at":1730000000}
```
Unauthenticated: 401 `unauthorized`.

### GET `/api/v1/auth/google`
Full-page redirect (not a JSON API call). Starts Google's OAuth2 authorization-code flow: sets short-lived `b1tm4p_oauth_state`/`b1tm4p_oauth_return` cookies (scoped to `/api/v1/auth/google`, 10 min TTL) and redirects to Google's consent screen. Optional `?return_to=/some/path` (must start with `/`) controls where the user lands after login; defaults to `/`. Returns `503 {"error":"google_oauth_not_configured"}` if `GOOGLE_CLIENT_ID` is unset.

### GET `/api/v1/auth/google/callback`
Google redirects here with `?code=&state=`. Verifies `state` against the cookie, exchanges `code` for tokens, fetches the Google userinfo endpoint, then: looks up `users.oauth_provider='google' AND oauth_id=<sub>`; if not found, looks up by email (links `oauth_provider`/`oauth_id` onto that existing account and sets `email_verified=1`); if still not found, creates a new `role='user'` account (`email_verified` set from Google's `email_verified` claim, `password_hash` a random unusable bcrypt hash, username derived from the email local-part with a numeric suffix on collision, initials avatar from the Google display name). Creates a session (same `b1tm4p_sid` cookie as password login), logs a `login_history` row, and redirects to `FRONTEND_ORIGIN + return_to`. On any failure, redirects to `FRONTEND_ORIGIN + /login?error=google_oauth_failed` instead of returning JSON (this is a browser redirect flow, not an API endpoint the frontend fetches).

`users.db` additionally has nullable `oauth_provider TEXT` and `oauth_id TEXT` columns (indexed together) for this; both are `NULL` for password-only accounts.

## Account and avatars

### PATCH `/api/v1/account`
Auth: required.
Request may contain `username`, `email`, or both. Email changes set `email_verified=0` and send a new verification email.
Response: updated user object. Errors: 400 `no_changes`, `invalid_username`, `invalid_email`; 409 `already_exists`.

### PATCH `/api/v1/account/password`
Auth: required.
Request: `{ "current_password":"oldpassword", "new_password":"newpassword" }`.
Response: `{ "ok":true }`. Errors: 403 `current_password_incorrect`; 400 `invalid_password`.

### PATCH `/api/v1/account/avatar`
Auth: required.
Request:
```json
{"avatar_type":"initials","avatar_value":"AB","avatar_shape":"circle","avatar_color":"#FF7A00"}
```
`avatar_type` is `initials` or `image`; initials require `avatar_value` matching `^[A-Z0-9]{1,2}$`; color is `#RRGGBB`; shape is `circle` or `square`. For JSON changes, image mode expects the existing stored image path as `avatar_value`.
Every request re-reads the role from `users.db`. `square` is accepted only for `manager` or `admin`; `user` and `support` receive 403 `square avatars reserved for staff`.
Response: updated user object.

### POST `/api/v1/account/avatar/upload`
Auth: required. Multipart field: `avatar`.
Accepted MIME types: JPEG, PNG, WebP, GIF. Maximum 5 MB. Server converts to 256x256 WebP and stores `/uploads/avatars/<userId>_<timestamp>.webp`; previous image avatar is deleted.
Response: updated user object. Invalid file: 400 `invalid_image`; multer limit errors: 400 `upload_error`.

## Tags

Slug generation lowercases, normalizes, replaces runs of non-alphanumeric characters with hyphens, trims edge hyphens, and uses `-2`, `-3`, etc. on collisions. Master-tag slugs are globally unique; tag slugs are unique within a master tag.

### GET `/api/v1/tags/master`
Auth: none. Paginated master-tag rows. Response `{items:[...],total:N}`.

### GET `/api/v1/tags/master/:slug`
Auth: none. Returns one master-tag row plus a `tags` array. 404 `not_found` if absent.

### GET `/api/v1/tags?master_slug=...`
Auth: none. Returns paginated tags. Unknown master slug returns an empty list.

### POST `/api/v1/tag-requests`
Auth: support/manager/admin.
Request for master: `{ "request_type":"master_tag", "proposed_name":"Photography" }`.
Request for tag: `{ "request_type":"tag", "proposed_name":"Portrait", "parent_master_tag_id":1 }`.
Response 201: created request row. Non-authorized users: 403 `forbidden`.

### GET `/api/v1/tag-requests?status=pending`
Auth: manager/admin. `status` may be pending, approved, rejected. Paginated request rows.

### POST `/api/v1/tag-requests/:id/approve`
Auth: manager/admin.
Optional body: `{ "review_note":"approved" }`.
Creates the requested master/tag row and marks request approved. 404 `not_found`, 409 `already_reviewed`/`conflict`.

### POST `/api/v1/tag-requests/:id/reject`
Auth: manager/admin. Optional `{ "review_note":"reason" }`. Marks pending request rejected.

### POST `/api/v1/tags/master`
Auth: manager/admin.
Request: `{ "name":"Photography", "description":"..." }`.
Response 201: master-tag row.

### POST `/api/v1/tags`
Auth: manager/admin.
Request: `{ "master_tag_id":1, "name":"Portrait" }`.
Response 201: tag row.

### PATCH `/api/v1/tags/master/:id`
Auth: manager/admin.
Request may contain `name` and/or `description`. Renaming regenerates the unique slug. Response: updated row.

### DELETE `/api/v1/tags/master/:id`
Auth: manager/admin.
Without `?force=true`, deletion is blocked with 409 `master_has_tags` when child tags exist. With `force=true`, child tags are deleted transactionally and then the master is deleted. Missing row: 404 `not_found`.

### PATCH `/api/v1/tags/:id`
Auth: manager/admin. Request `{ "name":"New Name" }`; regenerates unique per-master slug. Response: updated tag.

### DELETE `/api/v1/tags/:id`
Auth: manager/admin. Deletes tag. Response `{ "ok":true }`.

### POST `/api/v1/tags/master/:id/header`
Auth: manager/admin. Multipart field `header`. Any image MIME type is accepted up to `UPLOAD_MAX_MB`; Sharp validates image data. Stored below `/uploads/mastertag_headers/` and path is saved in `header_image_path`.
Response: `{ "header_image_path":"/uploads/mastertag_headers/<uuid>.<ext>" }`.

## Admin

### GET `/api/v1/admin/users`
Auth: admin. Paginated `{id,email,username,role,created_at}` rows.

### PATCH `/api/v1/admin/users/:id/role`
Auth: admin.
Request: `{ "role":"manager" }`; role must be `user`, `support`, `manager`, or `admin`.
Response: `{ "id":1, "role":"manager" }`.

### GET `/admin-raw`
Auth: admin. Non-admin authenticated users are redirected to `/`. Unauthenticated users receive 401 through auth middleware. Returns plain server-rendered HTML tables for users, login history, active sessions, and likes/reports counts. The latter are queried from separate read-only `content.db` and `reports.db` connections and silently remain zero if those files/tables do not yet exist.

## Content (posts, replies, likes)

Separate `content.db` (posts, replies, likes) opened by `backend/lib/contentDb.js`. Cross-references into `users.db`/`tags.db` are resolved in application code via read-only connections in `backend/lib/crossDb.js` — no `ATTACH`, no cross-file SQL joins.

### GET `/api/v1/posts?master_slug=&tag_slug=&search=&limit=&offset=`
Public. Returns `{ "items":[Post], "total":N }`, newest first, `deleted=0` only. `search` matches `body_text`/`header_title` (case-insensitive) and tag/master-tag name/slug.

**Post shape:**
```json
{
  "id":1,"master_tag_id":1,"tag_id":2,
  "author":{"id":5,"username":"alice","avatar_type":"initials","avatar_value":"AL","avatar_shape":"circle","avatar_color":"#FF7A00"},
  "master_tag":{"id":1,"name":"Photography","slug":"photography"},
  "tag":{"id":2,"name":"Portraits","slug":"portraits"},
  "header_title":"Hello","body_text":"...","body_type":"text","file_path":null,"file_mime":null,
  "created_at":1700000000,"likes_count":0,"reply_count":0,"deleted":false
}
```
Note: the list/detail response does not include the requesting user's own like state (`liked`); the frontend tracks this client-side after a like-toggle call.

### GET `/api/v1/posts/:id`
Public. Returns `{ "post":Post, "replies":[ReplyNode] }`. `replies` is the full nested tree (built from a `WITH RECURSIVE` query over `replies`). A deleted reply with visible descendants is returned as a `[deleted]` placeholder (`deleted:true`, null body/file) so tree structure is preserved; deleted leaves are omitted.

### POST `/api/v1/posts`
Auth required. `multipart/form-data`: `master_tag_id`, `tag_id`, `header_title?`, `body_text?` (for `body_type=text`), `body_type` (`text|image|sound|video`), `file` (required unless `body_type=text`). `tag_id` must belong to `master_tag_id` (checked against `tags.db`). Returns `201` with the full Post object.

### POST `/api/v1/posts/:id/reply`
Auth required. Same body fields as above plus optional `parent_reply_id` (nests under an existing reply in the same post). Increments the post's `reply_count`. Returns `201` with the Reply object (same shape as a reply node, without nested `replies`).

### DELETE `/api/v1/posts/:id` and `/api/v1/replies/:id`
Auth required; author or manager/admin only. Soft delete (`deleted=1`); rows are kept for thread integrity.

### POST `/api/v1/posts/:id/like` and `/api/v1/replies/:id/like`
Auth required. Toggles the current user's like (insert/delete on the `likes` UNIQUE constraint), recomputes `likes_count` on the content row. Returns `{ "liked":true|false, "likes_count":N }`.

## Reports

Separate `reports.db`, opened by `backend/lib/contentDb.js`.

### POST `/api/v1/reports`
Auth required. Body: `{ "content_type":"post"|"reply", "content_id":N, "reason":"..." }`. Validates the referenced content exists. Inserts a `pending` report.

### GET `/api/v1/reports?status=pending&limit=&offset=`
Manager/admin only. Returns `{ "items":[Report], "total":N }`. Each report includes `reporter` (id/username/avatar fields) and `content` (`body_text`/`body_type`/`file_path`/`deleted`/`snippet`, resolved from `content.db`).

### PATCH `/api/v1/reports/:id`
Manager/admin only. Body: `{ "status":"pending"|"reviewed"|"dismissed", "review_note"? }`. Sets `reviewed_by`/`reviewed_at` when leaving `pending`.

## Media uploads

Post/reply files are served statically from `/uploads/media/{images,sound,video}/...` (and avatar/master-tag-header uploads from `/uploads/avatars/...` and `/uploads/mastertag_headers/...`). Images are normalized to WebP (max 1600px longest edge) via `sharp`; sound/video are stored byte-for-byte, no transcoding. `UPLOAD_MAX_MB` governs the multer size limit for all of these.

## Infrastructure behavior

`docker-compose.yml` defines `backend`, `frontend`, and named volume `b1tm4p_data`. Backend maps host port 8080 to container 8080; frontend maps port 80. The backend Docker image is Node 20 Alpine and installs libvips/build prerequisites for Sharp.
